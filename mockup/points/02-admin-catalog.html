หมายเหตุ UX
  1. 1ประเภท: คูปอง / ส่งฟรี / ของแถม / เครดิต / สิทธิ์ลุ้น — ประเภทกำหนดว่าออกอะไรให้ลูกค้าและไปอยู่ที่ไหนหลังแลก (ตารางสรุปท้ายหน้า)
  2. 2ได้รับ: สรุปสั้นของสิ่งที่ลูกค้าจะได้ (สร้างอัตโนมัติจากฟิลด์ในรายการ) เพื่อให้แอดมินเห็นผลโดยไม่ต้องเปิดแก้ไข
  3. 3คงเหลือ / โควตารวม: ลดลงทันทีที่มีคนแลก · เหลือ 0 → สถานะอัตโนมัติเป็น "หมดแล้ว" และลูกค้ากดไม่ได้ · เติมโควตาได้ภายหลัง · ของแถมใช้สต็อกที่จัดสรรเป็นโควตา
  4. 4ต่อคน: จำกัดจำนวนครั้งต่อลูกค้า 1 บัญชี รายเดือน/รายปี/ตลอดไป — ว่าง = ไม่จำกัด · ตรวจที่ฝั่งเซิร์ฟเวอร์ตอนกดแลก
  5. 5สถานะ: เปิดใช้งาน / ปิดชั่วคราว (ซ่อนจากลูกค้า) / หมดแล้ว / รอเปิด (ตามช่วงเวลา) · ปิดชั่วคราวไม่กระทบสิทธิ์ที่ลูกค้าแลกไปแล้ว
  6. 6เปลี่ยนประเภทของรายการที่มีคนแลกแล้วไม่ได้: ต้องสร้างรายการใหม่ (กันสิทธิ์เก่าคลาดเคลื่อน) — ช่องประเภทจะเป็นอ่านอย่างเดียว
  7. 7ฟิลด์เปลี่ยนตามประเภท: คูปอง = ชนิด/มูลค่า/ขั้นต่ำ/อายุหลังแลก · ของแถม = สินค้า + สต็อก · เครดิต = บาท · สิทธิ์ลุ้น = กิจกรรม (ลิงก์ไปโมดูลสุ่มรางวัล)
  8. 8ของจริงเข้าคิวเดียวกับแคมเปญ: ลูกค้ากรอกที่อยู่แล้วทีมหลังบ้านจัดการต่อในคิวคำขอรับรางวัล — ไม่ต้องมีคิวแยกสำหรับพอยท์
  9. 9พอยท์ที่ใช้: เป็นจำนวนเต็ม > 0 · แก้ได้ตลอด มีผลกับการแลกครั้งถัดไป · ระบบเตือนถ้าตั้งต่ำกว่ามูลค่าของรางวัลจริงมากผิดปกติ
กติกา / ข้อยกเว้น / สถานะ
  • ลบรายการที่เคยมีคนแลกแล้วไม่ได้ — ทำได้เพียง "ปิดชั่วคราว" (เก็บประวัติไว้ตรวจย้อนหลัง) ; รายการที่ยังไม่เคยมีคนแลกลบได้
  • คูปองที่ได้จากการแลกเป็นคูปองออนไลน์ธรรมดาใบหนึ่ง (ผูกบัญชีลูกค้า ใช้ได้ครั้งเดียว) และใช้ตามกติกาคูปองทุกประการ
  • แลกสิทธิ์ลุ้นได้เฉพาะเมื่อกิจกรรมปลายทางเปิดอยู่ — ถ้ากิจกรรมปิด รายการจะแสดง "รอเปิด" และกดไม่ได้
  • ลูกค้าที่แลกเกินโควตาพร้อมกันหลายคน: ระบบตัดตามลำดับเวลาที่ชำระ ผู้ที่ช้ากว่าเห็นข้อความ "หมดแล้ว" และพอยท์ไม่ถูกหัก
ข้อที่ต้องตัดสินใจกับลูกค้า
  • เครดิตเงินคืนใช้ร่วมกับคูปอง/โปรโมชั่นในบิลเดียวกันได้หรือไม่ และมีอายุหรือไม่ (มอคอัพ: 90 วัน)
  • สิทธิ์ลุ้นที่แลกด้วยพอยท์นับเข้ากองทุนงบสุ่มรางวัลอย่างไร (กิจกรรมสุ่มรางวัลเป็นระยะถัดไป)
  • ของพรีเมียมที่ส่งไม่ได้/สต็อกจริงหมด หลังลูกค้าแลกแล้ว: คืนพอยท์ให้อัตโนมัติ หรือให้แอดมินตัดสินใจรายกรณี
