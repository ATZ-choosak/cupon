รางวัล
เลือกรางวัลจากกิจกรรม “ลุ้นโชคปลายปี 2569” แล้วเพิ่ม/แก้ผลตอบแทน — ค่าจะถูกใช้ตอนลูกค้าลุ้นเจอรางวัลนี้จริงในจำลอง

  1. 1ตัวเลข 4 ใบคำนวณสดทุกครั้งที่แก้น้ำหนัก/จำนวน/มูลค่า: ต้นทุนเฉลี่ย = Σ(น้ำหนัก × มูลค่า) ÷ น้ำหนักรวม; งบรวม = ต้นทุนเฉลี่ย × สิทธิ์ที่คาดไว้ (กรอกเองได้ ค่าเริ่มต้นจากรอบก่อน); ใบสุดท้ายเทียบกับเพดานงบ — แดงเมื่อเกิน เขียวเมื่ออยู่ในงบ
  2. 2เกินงบ = เตือนระดับ error: ปุ่ม "บันทึกรางวัล" ยังกดได้แต่ต้องมีผู้อนุมัติงบยืนยัน (กล่องยืนยันบันทึกชื่อผู้อนุมัติ) — ไม่ปล่อยให้บันทึกเงียบๆ
  3. 3เตือนรางวัลใหญ่ในโหมด A ตามสเปก 6.3 (เกณฑ์ ≥ ฿1,000/ชิ้น ปรับได้) พร้อมปุ่มย้ายไปโหมด B ในคลิกเดียว; ถ้าเลือก "คงไว้" ต้องระบุผู้อนุมัติ
  4. 4กรอก "น้ำหนัก" เป็นจำนวนเต็ม ≥ 0 เท่านั้น ไม่มีช่องเปอร์เซ็นต์ — "โอกาส" เป็นผลลัพธ์อ่านอย่างเดียว คำนวณจากน้ำหนักเฉพาะรางวัลที่ยังมีของ จึงรวมครบ 100% เสมอ
  5. 5รางวัลที่คงเหลือ = 0 ถูกตัดออกจากกองสุ่มทันที (แสดงชิป "หมด") และสัดส่วนที่เหลือเกลี่ยใหม่อัตโนมัติ; ตัวเลขโอกาสที่ลูกค้าเห็นเปลี่ยนตาม; ทุกการเกลี่ยบันทึกใน audit
  6. 6รางวัลโหมด B ไม่ใช้น้ำหนัก — ทุกสิทธิ์ในกองมีโอกาสเท่ากัน กรอก "จำนวนผู้ได้รับ" ซึ่งต้องประกาศก่อนเปิดกิจกรรมและเปลี่ยนลดลงไม่ได้หลังเปิด; งบ B จองทั้งก้อนล่วงหน้า
  7. 7ตัวคุมงบ: เพดานต่อรอบ/ต่อวัน, เพดานการถูกรางวัลต่อคน (แยกของทั่วไปกับรางวัลใหญ่), เพดานสิทธิ์สะสมต่อคน — ค่า "เมื่อชนเพดานงบ" ต้องเลือกให้ชัดเพราะกระทบประสบการณ์ลูกค้า
  8. 8การันตีของปลอบใจ: นับพลาดติดกันต่อคนต่อกิจกรรม ถึง N ครั้งการลุ้นครั้งถัดไปได้ของปลอบใจแน่นอน; ลูกค้าเห็นตัวนับในหน้าลุ้น (หน้า 07)
  9. 9จำลอง 10,000 ครั้งเป็นค่าคาดหวัง (น้ำหนัก × 10,000) ไม่ใช่การสุ่มจริง — ใช้ดูว่ารางวัลไหนจะหมดก่อน และเส้นเพดานงบจะชนที่ครั้งที่เท่าไร; "จำลองซ้ำ" สุ่มด้วยเมล็ดใหม่เพื่อดูความแกว่ง
  10. 10ผลตอบแทนของแต่ละรางวัล เปลี่ยน ไม่มี “เพิ่มรางวัลจากชุดของรางวัล” แล้ว — ตั้งตรงนี้ด้วย component ผลตอบแทนเดียวกับทุกโมดูล (พอยท์ · คูปอง · ของแถม SKU · เครดิต · สิทธิ์ลุ้น · ของนอก POS) เพิ่มได้หลายอย่างต่อรางวัล เก็บแยกตามรางวัล ติดธง source_module = raffle · ลองลุ้นจริงที่สถานะลูกค้าของจำลอง
กติกา / ข้อยกเว้น / สถานะ
  • แก้น้ำหนัก/จำนวนระหว่างเปิดกิจกรรม: มีผลกับการลุ้นครั้งถัดไปเท่านั้น และทุกการแก้บันทึกเป็นเวอร์ชันพร้อมผู้แก้ (นำไปแสดงใน snapshot ของหน้าบันทึกการลุ้น)
  • รางวัลที่มีคนถูกไปแล้วลบไม่ได้ — ตั้งจำนวนคงเหลือเป็น 0 ได้อย่างเดียว
  • มูลค่า/ชิ้นของรางวัลพอยท์คิดตามมูลค่าพอยท์ที่ตั้งไว้ (ที่นี่ 10 พอยท์ = ฿1)
  • การันตีของปลอบใจเป็นรางวัลมีต้นทุนจึงต้องมีมูลค่า > 0 หรือเลือกชนิดที่ไม่มีต้นทุน เช่น คูปองหมดอายุเร็ว
ข้อที่ต้องตัดสินใจกับลูกค้า
  • เมื่อชนเพดานงบโหมด A ให้ "ออกผลไม่ถูกต่อ" (เสนอ) หรือ "หยุดรับการลุ้น" — เสนอแบบแรกเพื่อไม่ให้ลูกค้ากดแล้วใช้ไม่ได้ แต่ฝ่ายกฎหมายควรเห็นชอบว่าไม่เข้าข่ายหลอกลวง
  • เปิดเผยโอกาส % ให้ลูกค้าเห็นหรือไม่ (เสนอ: เปิด — โปร่งใสตามสเปก 6.6) และแสดงเป็นเปอร์เซ็นต์จริงหรือเป็นช่วง
  • เกณฑ์ "รางวัลใหญ่" ที่ระบบเตือน/แนะนำโหมด B (เสนอ ≥ ฿1,000/ชิ้น)
  • ต้นทุนของปลอบใจที่การันตีนับรวมในงบรอบหรือแยกงบต่างหาก (เสนอ: นับรวม)
