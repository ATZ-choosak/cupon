กติกาหลัก
  • ไม่ต้องใส่โค้ด โปรเกิดขึ้นเองเมื่อตะกร้าเข้าเงื่อนไข ยอดที่ชำระคำนวณที่เซิร์ฟเวอร์เสมอ
  • ตั้งค่าหน้าเดียวกับเซตของแถมเดิม ขยายผลตอบแทนเป็นของแถม / ส่วนลด / ฟรีค่าจัดส่ง ไม่แยกหน้าตั้งค่า
  • หลายโปรตรงพร้อมกัน ใช้ลำดับ priority สูงสุด (#1 ก่อน) · โปรแบบแบรนด์/หมวดที่แย่งกลุ่มสินค้าเดียวกัน ชนะ 1 โปร ไม่บวกซ้อน
  • ผลตอบแทนคิดเฉพาะรายการที่เข้าเงื่อนไข ไม่ใช่ทั้งบิล
  • ให้ผลตอบแทน 1 ครั้งต่อบิล ซื้อเกินเงื่อนไขกี่เท่าก็ได้ผลตอบแทนเท่าเดิม
  • โควต้าต่อลูกค้า นับเป็นจำนวนครั้งที่รับสิทธิ์ · ของแถมหมดสต็อก = ปิดโปรชั่วคราวและแจ้งแอดมิน
  • ยกเลิก/คืนสินค้าไม่เรียกคืนสิทธิ์ ที่ใช้ไปแล้ว (นโยบายร่วมของระบบ)
สถานะของสิ่งที่ลูกค้าได้รับ
ใกล้ถึงเงื่อนไขยังไม่ครบ แต่ใกล้แล้ว เช่น "อีก 2 ลัง รับโปรขั้น 2" (แสดงในหน้าสินค้า/ตะกร้า) ได้รับสิทธิ์ในตะกร้าเข้าเงื่อนไขและชนะ priority — เห็นของแถม/ส่วนลดในตะกร้าแล้ว ผ่านเงื่อนไข แต่ไม่ถูกใช้แพ้โปรที่ priority สูงกว่า หรือสินค้าชุดเดียวกันถูกใช้ไปแล้ว ใช้งานแล้วออเดอร์ยืนยันแล้ว — บันทึกในประวัติการใช้งาน นับโควต้า โควต้าเต็มแล้วใช้ครบตามโควต้าต่อลูกค้า — ปุ่มถูกปิด ยังไม่เริ่มต้นถึงวันเริ่มแล้วจึงใช้ได้ — การ์ดยังเห็นเพื่อประกาศล่วงหน้า หมดอายุพ้นวันสิ้นสุด — ไม่แสดงในหน้ารวม หยุดชั่วคราว (ของแถมหมด)ระบบปิดให้อัตโนมัติ — ไม่ถูกคิดในตะกร้า จนกว่าแอดมินเปิดอีกครั้ง
เชื่อมกับโมดูลอื่นอย่างไร
  • ลำดับการคิดเงิน Flash Sale (ลดราคาสินค้า) → โปรโมชั่น → คูปอง → ค่าจัดส่ง → ใช้พอยท์ — แต่ละขั้นคิดต่อจากยอดคงเหลือของขั้นก่อนหน้า
  • คูปอง ใช้ร่วมได้หรือไม่ตั้งที่ตัวโปร (และนโยบายร่วม) · คูปองไม่ลดซ้ำกับรายการที่โปรจับคู่แล้ว ถ้าตั้งว่าไม่ใช้ร่วม
  • พอยท์ พอยท์ที่ได้คิดรายสินค้าตามจำนวนที่ซื้อ ไม่เปลี่ยนตามส่วนลดโปร · ของแถมได้ 0 พอยท์ (ค่าเริ่มต้น)
  • แคมเปญ / สุ่มรางวัล ยอดซื้อสะสมแคมเปญนับจากยอดสินค้าที่เข้าร่วม — โปรแถมไม่เพิ่มยอดสะสม
  • ใบสั่งซื้อ / POS ของแถมเป็นบรรทัด ฿0 ในออเดอร์ ตัดสต็อกจริงและส่งต่อ POS
หมายเหตุ UX
  1. 1สร้างโปร เริ่มจากกล่องเดียว ใช้ฟอร์มเดียวกับ Bundle เดิม — ส่วนที่เพิ่มใหม่มีป้าย "ใหม่": ผลตอบแทน 3 แบบ ขอบเขตแบรนด์/หมวด ใช้ร่วมกับสิทธิ์อื่น (หน้า 02) · กลุ่มขั้นบันไดแยกหน้า 03 · ลดตามวันพิเศษแยกหน้า 04
  2. 2จำลองตะกร้า เป็นขั้นแนะนำ ไม่บังคับ — ใช้ตรวจว่าโปรใหม่ไปชนโปรเดิมหรือไม่ก่อนเปิดใช้งาน (ทดสอบโปรที่ยังปิดอยู่ได้)
  3. 3จัดลำดับ ลากแถวในตาราง ตัวเลข #1 = สูงสุด ระบบบันทึกทันที (เหมือน Bundle เดิม) — แนะนำจัดหลังสร้างโปรใหม่ทุกครั้ง เพราะโปรใหม่ถูกวางท้ายสุดโดยค่าเริ่มต้น
  4. 4เปิดใช้งาน สถานะแสดงตามวันที่เริ่ม–สิ้นสุด (ใช้งาน / ยังไม่เริ่มต้น / หมดอายุ) บันทึกเป็น "ใช้งาน" ไม่ได้ถ้ายังไม่มีสินค้าที่ต้องมีและผลตอบแทน
  5. 5แท็กบนการ์ดสินค้า ป้ายเดียวต่อประเภทผลตอบแทนของโปรที่ชนะ/ใกล้ถึง ไม่แสดงตัวเลข priority ให้ลูกค้าเห็น
  6. 6ตรวจเงื่อนไข ทำใหม่ทุกครั้งที่จำนวนหรือรายการในตะกร้าเปลี่ยน ไม่ใช้ผลที่จำไว้จากหน้าก่อน
  7. 7เลือกโปร จัดกลุ่มตามสินค้าที่ใช้ร่วมกัน — ภายในกลุ่มเดียวกัน priority สูงสุดที่ผ่านเงื่อนไขชนะ 1 โปร โปรที่แพ้ถูกบันทึกเหตุผลไว้โชว์ในตะกร้า/จำลองตะกร้า
  8. 8คำนวณ ผลตอบแทนอิงเฉพาะบรรทัดที่เข้าเงื่อนไข · ให้ผลตอบแทน 1 ชุดต่อบิล (ต่อออเดอร์ที่เข้าเงื่อนไข)
  9. 9ตรวจโควตา/สต็อก ถ้าโควต้าต่อคนเต็ม โปรไม่ถูกใช้ (ปุ่มหน้าลูกค้าแสดง "โควต้าเต็มแล้ว") · ถ้าของแถมไม่พอสำหรับชุดที่ได้ ระบบให้เท่าที่สต็อกพอ ถ้าเหลือ 0 ไปข้อ 11
  10. 10บันทึกการใช้สิทธิ์ เกิดตอนออเดอร์ยืนยัน/ชำระสำเร็จ ไม่ใช่ตอนใส่ตะกร้า — จึงไม่ต้องมีการพักโควตา (ต่างจากแคมเปญโควตา)
  11. 11ของแถมหมดสต็อก ระบบปิดโปรชั่วคราวทันที ตะกร้าที่มีโปรนี้อยู่จะไม่ได้ของแถมและแสดงข้อความอธิบาย (หน้า 09)
  12. 12รับแจ้งเตือน แอดมินเห็นป้ายแดง "ปิดชั่วคราว: ของแถมหมด" ที่แถวโปรในหน้ารายการ (หน้า 01) เติมสต็อกแล้วกดเปิดใช้งานเอง
กติกา / ข้อยกเว้น / สถานะ
  • โปรที่ถูกปิดชั่วคราวเพราะของแถมหมดจะไม่เปิดคืนเอง แม้เติมสต็อกแล้ว แอดมินต้องกดเปิดเอง (ค่าเริ่มต้น)
  • แก้ไขโปรที่มีผู้ใช้สิทธิ์ไปแล้ว มีผลกับตะกร้า/ออเดอร์ใหม่เท่านั้น ประวัติเดิมไม่เปลี่ยน
  • ลูกค้าเห็นโปรเฉพาะที่ active และอยู่ในช่วงเวลา · โปร "ยังไม่เริ่มต้น" แสดงเป็นการ์ดเทาและกดไม่ได้
ข้อที่ต้องตัดสินใจกับลูกค้า
  • โปรที่ถูกปิดชั่วคราวเพราะของแถมหมด: ให้เปิดคืนอัตโนมัติเมื่อมีสต็อก หรือให้แอดมินเปิดเอง (ค่าเริ่มต้นในมอคอัพ = แอดมินเปิดเอง)
  • ยอดที่ใช้นับเงื่อนไขโปรคิดจากราคาก่อนหรือหลังลด Flash Sale (ค่าเริ่มต้น = หลังลด คือราคาที่ลูกค้าจ่ายจริง)
