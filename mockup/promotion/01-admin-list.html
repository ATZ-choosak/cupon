โปรโมชั่น

จัดการโปรโมชั่นตามเงื่อนไข และลดตามวันพิเศษ — ผลตอบแทนผสมได้หลายอย่าง (ของแถม ส่วนลด ฟรีค่าส่ง พอยท์ คูปอง เครดิต สิทธิ์ลุ้น ของนอก POS)

จำลองตะกร้า (โมดูลใหม่) ＋ สร้างโปรโมชั่น
ไม่มีลำดับความสำคัญ (priority) แล้ว — ถ้าตะกร้าของลูกค้าเข้าเงื่อนไขหลายโปร ลูกค้าเลือกเองเป็นการ์ดในตะกร้า ระบบทำโปรที่ใช้ร่วมกันไม่ได้เป็นสีเทาให้ · กำหนด “ใช้ร่วมกับโปรอื่นได้/ไม่ได้” ที่หน้าแก้ไขแต่ละโปร
ข้อมูลในตารางด้านล่างดึงจากชุดเดียวกับตั้งค่าจำลอง — กดเปิด/ปิด ทำซ้ำ ลบ ได้จริง และสถานะคำนวณจากวันที่จำลอง

หมายเหตุ UX
  1. 1ผลตอบแทน เปลี่ยน โปรหนึ่งโปรมีหลายผลตอบแทนพร้อมกันได้ แสดงเป็น chip ต่อชนิด (ของแถม ส่วนลด ฟรีค่าส่ง พอยท์ คูปอง เครดิต สิทธิ์ลุ้น ของนอก POS) · กรองได้ตามชนิดที่มีอยู่ในโปร
  2. 2แท็บสถานะ ใหม่ โปรโมชั่นตามเงื่อนไข · ลดตามวันพิเศษ · ยังไม่เริ่ม · หมดอายุ · ไม่ใช้งาน · หมดโควต้า — แท็บ 1–2 แสดงโปรที่กำลังใช้งาน ส่วนแท็บที่เหลือแสดงตามสถานะ (นับจากวันที่ + สวิตช์ + โควต้า)
  3. 3โควต้าทั้งหมด ใหม่ ใช้แล้ว / ทั้งหมด (ทุกคนรวมกัน) + แถบความคืบหน้า · เต็มแล้วเปลี่ยนเป็น “หมดโควต้า” เอง และเลือกไม่ได้ในตะกร้า · คอลัมน์ “ต่อคน” คือโควต้าต่อลูกค้า
  4. 4การดำเนินการ แก้ไข / เปิด-ปิดใช้งาน / ทำซ้ำ / ลบ ทำงานจริงกับข้อมูลตั้งค่าจำลอง · ทำซ้ำสร้าง “(สำเนา)” สถานะไม่ใช้งาน · ไม่มีการลากเรียงลำดับ
  5. 5ลดตามวันพิเศษ (Flash) ยังเป็นหน้าเฉพาะ (กลุ่มสินค้า + โควตารอบ) ราคา Flash ถูกคิดก่อนโปรเงื่อนไข
กติกา / ข้อยกเว้น / สถานะ
  • ลำดับ priority ถูกถอดออกทั้งระบบ: ลูกค้าเลือกโปรเอง · ระบบเทาโปรที่ใช้ร่วมกันไม่ได้ · ถ้าเลือกอยู่แล้วโปรชนกัน ระบบสลับให้ตามที่ลูกค้ากด
  • สิทธิ์จัดการ: ROLE_MARKETING, ROLE_PRODUCT — บทบาทอื่นเห็นข้อความ “คุณไม่มีสิทธิ์เข้าถึง”
  • โปรเดิมที่เป็นเซตของแถม (Bundle) ถูกย้ายเข้ารายการนี้ ผลตอบแทน = ของแถม ขอบเขต = เลือกรายสินค้า
  • ลบโปรที่มีประวัติใช้สิทธิ์: ซ่อนจากรายการ เก็บประวัติไว้ (soft delete)
