โปรโมชั่น

โปรโมชั่นมี 2 แบบ — ตามเงื่อนไข (ซื้อครบแล้วได้ผลตอบแทน) และ ลดตามช่วงเวลา (Flash Sale) (ลดราคาสินค้าเป็นช่วงเวลา) · เลือกแบบจากการ์ดด้านล่าง

จำลองตะกร้า ＋ สร้างโปรโมชั่นตามเงื่อนไข
1
ไม่มีลำดับความสำคัญ (priority) — ถ้าตะกร้าเข้าเงื่อนไขหลายโปร (แบบตามเงื่อนไข) ลูกค้าเลือกเองเป็นการ์ด โปรที่ใช้ร่วมกันไม่ได้จะถูกเทา · ราคา Flash ถูกคิดก่อนเสมอ แล้วโปรตามเงื่อนไขคิดต่อจากราคานั้น

หมายเหตุ UX
  1. 1เลือกแบบโปรโมชั่น ใหม่ โปรโมชั่นแยกเป็น 2 แบบในเมนูเดียว เพราะกลไกต่างกัน: ตามเงื่อนไข = ซื้อครบแล้วได้ผลตอบแทน ลูกค้าเลือกการ์ดเอง · ลดตามช่วงเวลา (Flash Sale) = ลดราคาตามกลุ่มสินค้าเป็นช่วงเวลา ไม่มีเงื่อนไข ไม่ต้องเลือก · การ์ดแต่ละใบมีคำอธิบาย ตัวอย่าง และจำนวนรายการ · กดแล้วตารางด้านล่างเปลี่ยน และปุ่ม “＋ สร้าง…” เปลี่ยนตามแบบที่เลือก
  2. 2ผลตอบแทน โปรตามเงื่อนไขมีหลายผลตอบแทนพร้อมกันได้ แสดงเป็นชิปตามชนิด (พอยท์ มีทั้งตัวคูณและพอยท์ฟรี)
  3. 3โควต้าทั้งหมด ใช้แล้ว / ทั้งหมด (ทุกคนรวมกัน) + แถบความคืบหน้า · ว่าง = ไม่จำกัด
  4. 4การดำเนินการ แก้ไข / เปิด-ปิดใช้งาน / ทำซ้ำ / ลบ ทำงานจริงกับข้อมูลตั้งค่าจำลอง
  5. 5Flash Sale ตั้งส่วนลด % ต่อกลุ่มสินค้า + โควตารอบ + เกิดซ้ำ ที่หน้าตั้งค่าของตัวเอง (กลไกต่างจากแบบตามเงื่อนไข จึงไม่รวมฟอร์มเดียวกัน) · แท็บสถานะ: ใช้งานอยู่ / ยังไม่เริ่ม / หมดอายุ / ปิดใช้งาน
กติกา / ข้อยกเว้น / สถานะ
  • ลำดับ priority ถูกถอดออกทั้งระบบ: ลูกค้าเลือกโปรเอง · ระบบเทาโปรที่ใช้ร่วมกันไม่ได้
  • ถ้าสินค้าอยู่ทั้งใน Flash Sale และโปรตามเงื่อนไข: ลด Flash ก่อน แล้วโปรตามเงื่อนไขคิดต่อจากราคา Flash
  • โปรวันพิเศษที่ต้องการผลตอบแทนอื่น (เช่น พอยท์ ×2) ให้สร้างเป็น “โปรตามเงื่อนไข” แบบไม่มียอดขั้นต่ำ — Flash Sale ลดราคาอย่างเดียว
  • สิทธิ์จัดการ: ROLE_MARKETING, ROLE_PRODUCT — บทบาทอื่นเห็นข้อความ “คุณไม่มีสิทธิ์เข้าถึง”
  • ลบโปรที่มีประวัติใช้สิทธิ์: ซ่อนจากรายการ เก็บประวัติไว้ (soft delete)
ข้อที่ต้องตัดสินใจกับลูกค้า
  • จะรวม Flash Sale เข้าฟอร์มโปรโมชั่นเดียว (เงื่อนไข = ไม่มี, ผลตอบแทน = ส่วนลดต่อกลุ่มสินค้า + โควตารอบ + เกิดซ้ำ) หรือคงแยก 2 แบบตามมอคอัพนี้ — มอคอัพเสนอแยก เพราะต้องมีส่วนลดต่างกันต่อกลุ่มสินค้า และราคาต้องขึ้นที่การ์ดสินค้าโดยตรง
