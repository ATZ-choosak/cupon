มีประวัติการใช้สิทธิ์ 203 ครั้ง — ประวัติและออเดอร์เดิมไม่ถูกลบ
หมายเหตุ UX
  1. 1ลำดับความสำคัญ เรียงจากบนลงล่าง #1 = สูงสุด ลากที่จับ ⋮⋮ เพื่อสลับ ระบบบันทึกทันทีและแสดง toast "อัปเดตลำดับโปรโมชั่นสำเร็จ" (เหมือน Bundle เดิม) · เลข # คือตำแหน่งในรายการ ไม่ใช่ค่าที่พิมพ์เอง · ขณะกรอง/ค้นหาจะลากไม่ได้ (กันสลับผิดตำแหน่ง)
  2. 2ประเภทผลตอบแทน ใหม่ chip สีบอกชนิด: ของแถม / ส่วนลด (฿ หรือ %) / ส่งฟรี · กรองได้จาก dropdown ด้านบน
  3. 3ใช้ไปแล้ว ใหม่ จำนวนครั้งที่ลูกค้ารับสิทธิ์ทั้งหมด (นับจากออเดอร์ที่ยืนยันแล้ว) ใต้ตัวเลขคือโควต้า/คน ที่ตั้งไว้ · กดตัวเลขเพื่อดูประวัติ (ออเดอร์ ลูกค้า วันที่)
  4. 4เปิด/ปิดใช้งานหลายรายการ ใหม่ ติ๊กแถวแล้วแถบนี้ปรากฏ · เปิดใช้งานแถวที่ยังไม่มีสินค้าที่ต้องมีหรือผลตอบแทนไม่ได้ ระบบข้ามแถวนั้นและแจ้งรายชื่อที่ข้าม
  5. 5สถานะ คำนวณจากวันที่ + สวิตช์ใช้งาน (เหมือนเดิม): ใช้งาน / ยังไม่เริ่มต้น / หมดอายุ / ไม่ใช้งาน · ป้ายแดงเสริม "ปิดชั่วคราว · ของแถมหมด" ที่ระบบตั้งให้เอง พร้อมเวลา และไม่เปิดคืนเอง
  6. 6การดำเนินการ แก้ไข / ทำซ้ำ ใหม่ / ลบ · ทำซ้ำสร้างสำเนา "(สำเนา)" สถานะไม่ใช้งาน วางท้ายสุดของลำดับ · แก้ไขโปรที่ถูกใช้แล้วมีผลกับตะกร้าใหม่เท่านั้น
  7. 7ยืนยันลบ ใช้ dialog เดิม ใช่/ไม่ · ถ้ามีประวัติการใช้สิทธิ์ แสดงจำนวนใน dialog และแนะนำให้ "ปิดใช้งาน" แทน
กติกา / ข้อยกเว้น / สถานะ
  • แท็บ "ลดตามวันพิเศษ" ใช้ข้อมูลคนละชุดกับโปรเงื่อนไข ไม่มีลำดับ priority — ราคาลด Flash ถูกคิดก่อน แล้วจึงตรวจโปรเงื่อนไข
  • แถวที่หมดอายุ/ยังไม่เริ่มยังลากเรียงได้ (เพื่อเตรียมลำดับก่อนถึงวันเริ่ม)
  • สิทธิ์จัดการ: ROLE_MARKETING, ROLE_PRODUCT (เหมือนหน้าเซตของแถมเดิม) — บทบาทอื่นเห็นข้อความ "คุณไม่มีสิทธิ์เข้าถึง"
  • โปรเดิมที่เป็นเซตของแถมอยู่แล้ว ถูกย้ายเข้ารายการนี้ตามเดิม (ผลตอบแทน = ของแถม ขอบเขต = เลือกรายสินค้า) ไม่ต้องตั้งค่าใหม่
ข้อที่ต้องตัดสินใจกับลูกค้า
  • ลบโปรที่มีประวัติใช้สิทธิ์แล้ว: ค่าเริ่มต้น = ซ่อนจากรายการและเก็บประวัติไว้ (soft delete) หรือห้ามลบ ให้ปิดใช้งานอย่างเดียว
  • โปรที่ระบบปิดชั่วคราวเพราะของแถมหมด: เปิดคืนอัตโนมัติเมื่อมีสต็อก หรือให้แอดมินกดเปิดเอง (ค่าเริ่มต้น = แอดมินเปิดเอง)
