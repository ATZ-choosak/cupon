กติกาหลัก
  • เฉพาะบัญชีร้านค้า (B2B) สั่งได้ — บัญชีทั่วไป (B2C) เห็นหน้าเซตแต่สั่งไม่ได้
  • สินค้าบังคับ ถอดออกไม่ได้ · ต้องไม่ต่ำกว่าจำนวนขั้นต่ำที่แอดมินกำหนด · แสดงล็อกพร้อมป้าย "บังคับ"
  • สินค้าทางเลือก เปิด-ปิดได้ · เปิดแล้วใช้จำนวนแนะนำเป็นค่าเริ่มต้น · ปิดแล้วจำนวน = 0
  • ราคาเซตรวม = Σบังคับ + Σทางเลือกที่เลือก − ส่วนลดชุดเซต · เช่น 25,000 + 3,500 − 2,000 = ฿26,500 · คำนวณใหม่ทุกครั้งที่สลับ/ปรับจำนวน
  • บังคับหมดสต็อก → บล็อกทั้งเซตจนแอดมินเติมสต็อก · ทางเลือกหมด → ปิดอัตโนมัติ เซตยังสั่งได้
  • ลูกค้าสั่งเองบนเว็บ หรือ แอดมิน/เซลล์สั่งแทน — ราคาและเงื่อนไขชุดเดียวกัน ไม่มีการ override
  • สั่งทั้งเซตเป็น ออเดอร์เดียว ผูกส่วนลดชุดเซตเป็นบรรทัดส่วนลดของออเดอร์นั้น
สถานะของสิ่งที่ลูกค้าได้รับ
ขายเซตเปิดขาย สินค้าบังคับครบ — ลูกค้า B2B สั่งได้ สต็อกไม่พอมีสินค้าบังคับต่ำกว่าขั้นต่ำ/หมด — บล็อกทั้งเซต ปุ่มใส่ตะกร้าใช้ไม่ได้ ปิดแอดมินปิดการขาย — ไม่แสดงในหน้าเซตของลูกค้า บังคับแถวล็อก ถอดไม่ได้ ปรับจำนวนได้ไม่ต่ำกว่าขั้นต่ำ ทางเลือก · เลือกนับรวมในราคา ปรับจำนวนได้ ทางเลือก · ไม่เลือกไม่นับรวมในราคา (จำนวน 0) หมดสต็อก · ปิดอัตโนมัติสวิตช์ปิดและกดไม่ได้ ราคาคำนวณใหม่แล้ว บัญชีทั่วไป สั่งไม่ได้ไม่ใช่ B2B — แสดงปุ่มขออัปเกรด
เชื่อมกับโมดูลอื่นอย่างไร
โปรโมชั่น / เซตของแถม
ข้อเสนอ: สินค้าในเซตร้านยาไม่ถูกนับซ้ำในโปรโมชั่นรายสินค้า/เซตของแถม — ส่วนลดชุดเซตเป็นส่วนลดเดียวของบรรทัดนี้
คูปอง
ข้อเสนอ: คูปองออนไลน์ใช้กับยอดออเดอร์เซตได้ตามเงื่อนไขขั้นต่ำของคูปอง แต่ไม่ซ้อนกับส่วนลดชุดเซตซ้ำบรรทัดเดียวกัน
พอยท์
ข้อเสนอ: คิดพอยท์จากยอดสุทธิหลังหักส่วนลดชุด ตามอัตราพอยท์รายสินค้าของแต่ละบรรทัด
แคมเปญสะสมยอดรายปี
ข้อเสนอ: ยอดสุทธิของเซตนับเข้ายอดสะสมของร้านค้าเมื่อออเดอร์ชำระแล้ว
สุ่มรางวัล
ข้อเสนอ: ออเดอร์เซตเป็นทางเข้าสิทธิ์ได้ถ้ากิจกรรมตั้งไว้ตามยอดสั่งซื้อ
คำสั่งซื้อ / สต็อก / ลูกค้า
ออเดอร์เซตตัดสต็อกรายสินค้าเหมือนออเดอร์ปกติ · ใช้ตรวจสอบสิทธิ์ B2B จากประเภทลูกค้าเดิมของ pmpc
หมายเหตุ UX
  1. 1กำหนดบังคับ / ทางเลือก / ส่วนลด — แอดมินต้องมีสินค้าบังคับอย่างน้อย 1 รายการ และสินค้าเดียวกันห้ามอยู่ทั้งสองรายการ ถึงจะเปิดขายได้ (รายละเอียดที่หน้า 02)
  2. 2ตรวจสิทธิ์ B2B — ตรวจจากประเภทบัญชีที่ผูกกับผู้ล็อกอิน ทุกครั้งที่เปิดหน้าเซต ใส่ตะกร้า และเช็คเอาต์ (ไม่เชื่อค่าที่ค้างในหน้า)
  3. 3ตรวจสต็อก — แยกผลเป็น 2 แบบ: สินค้าบังคับต่ำกว่าขั้นต่ำ = บล็อกทั้งเซต, สินค้าทางเลือกไม่พอ = ปิดอัตโนมัติและแจ้งลูกค้า
  4. 4ดูราคาสด — ราคาใหม่แสดงทันทีบนฝั่งหน้าจอ และเซิร์ฟเวอร์คำนวณซ้ำด้วยสูตรเดียวกันทุกครั้งที่ใส่ตะกร้า/เช็คเอาต์ (ราคาที่หน้าจอไม่ใช่ราคาที่เชื่อถือได้)
  5. 5ออเดอร์เดียวทั้งเซต — ทุกบรรทัดสินค้ามีป้ายชื่อเซต + ประเภท (บังคับ/ทางเลือก) ติดไว้ ใช้ตอนเคลม/คืนสินค้า/รายงาน
  6. 6สั่งแทนลูกค้า — ผ่านทางเดียวกับลูกค้า ใช้ตรวจสิทธิ์ B2B ตัวเดียวกัน และบันทึกผู้สั่ง (staff) ไว้ในออเดอร์
  7. 7บังคับหมดสต็อก — บล็อกเฉพาะการสั่ง ลูกค้ายังเปิดดูเซตได้ และกด "แจ้งเตือนเมื่อพร้อม" ได้
กติกา / ข้อยกเว้น / สถานะ
  • สถานะ "สต็อกไม่พอ" ของเซตคำนวณอัตโนมัติจากสินค้าบังคับ — ไม่ใช่สถานะที่แอดมินตั้งเอง; ปิดการขายเป็นอีกสถานะที่แอดมินตั้ง
  • เมื่อแอดมินแก้ราคา/จำนวนขั้นต่ำของเซตที่มีอยู่ในตะกร้าลูกค้า ตะกร้าจะคำนวณใหม่ตอนเปิด และแจ้ง "ราคาเซตมีการเปลี่ยนแปลง"
  • ออเดอร์ที่สร้างแล้วเก็บราคา ณ เวลาสั่ง ไม่ถูกคำนวณย้อนหลังเมื่อแอดมินแก้เซต
ข้อที่ต้องตัดสินใจกับลูกค้า
  • ส่วนลดชุดเซตใช้ร่วมกับโปรโมชั่นรายสินค้า / คูปอง / พอยท์ ได้หรือไม่ (เสนอ: ไม่ซ้อนกับโปรรายสินค้า, คูปองได้, พอยท์คิดจากยอดสุทธิ)
  • ยอดเซตนับเข้าแคมเปญสะสมยอดรายปีและสิทธิ์ลุ้นรางวัลหรือไม่ (เสนอ: นับ)
  • ลูกค้าสั่งได้กี่เซตต่อออเดอร์ (เสนอ: 1 เซตต่อออเดอร์ ถ้าต้องการเพิ่มให้สั่งซ้ำ)
  • ราคาต่อหน่วยในเซตผูกกับราคาสินค้าปัจจุบัน (ขยับตามเมื่อแก้ราคาสินค้า) หรือล็อกราคาไว้ในเซต (เสนอ: ตามราคาสินค้าปัจจุบัน)
