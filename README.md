# จำลองระบบโปรโมชั่น — Pharmaplex

Prototype ไม่ต้อง build ไม่ต้องมี server — เปิดไฟล์ .html ตรงในเบราว์เซอร์ได้เลย มีเมนูสลับหน้ากันได้ (มุมบนซ้าย)

## วิธีเปิด

ดับเบิลคลิก `showcase.html` (หน้าหลัก — ภาพรวมระบบ, สำหรับนำเสนอลูกค้า) แล้วกดเมนู "ระบบจำลอง" หรือ "ตั้งค่าแอดมิน" เพื่อไปหน้าที่กดเล่นได้จริง

**เคล็ดลับตอนนำเสนอ**: เปิด `admin.html` กับ `index.html` คู่กันคนละแท็บ — แก้ค่าฝั่งแอดมินแล้วสลับไปแท็บ `index.html` จะเห็นผลจริงทันที (sync กันผ่าน `localStorage`)

## ไฟล์ในนี้

- `showcase.html` + `showcase.css` — **หน้าภาพรวม** สำหรับนำเสนอลูกค้า เน้นภาพ กดโต้ตอบได้บางส่วน ครอบคลุมทุกฟีเจอร์: โปรโมชั่น (ซื้อคู่สินค้าลดราคา, ลดตามวัน, ส่วนลดท้ายบิล/ส่งฟรี), คูปอง (กระดาษพิมพ์แจกหน้าบูท, เก็บล่วงหน้า/แจกอัตโนมัติทุกเดือน — setting เดียวกัน), สะสมพอยท์, แคมเปญ (ขั้นบันไดล้วน — ตั้งโควตาน้อยๆ = คนแรกถึงเกณฑ์ในตัว, เว้นโควตาว่าง = ของหายากที่คัดเลือกนอกระบบ)
- `index.html` + `shop.js` + `shop.css` — **ระบบจำลองเดียว** แทนที่ระบบ A/B เดิมทั้งหมด จำลองลูกค้าจริงเข้ามาเลือกซื้อสินค้า: หยิบของใส่ตะกร้า → ราคาปรับสดตาม Flash Sale → การ์ดแนะนำ "ซื้อคู่กัน" คำนวณจากของในตะกร้าจริง → ส่วนลดท้ายบิล (priority สูงสุดชนะ) → ใช้คูปอง (พิมพ์โค้ด หรือกดเก็บจากกระเป๋า — เห็นผลตรวจสอบสด ไม่สลับคูปองเงียบๆ ต้องเอาอันเดิมออกก่อนเสมอ) → ค่าส่งคิดตามกลุ่มสินค้า → กด "ชำระเงิน" จริง **ยอดสะสมแคมเปญบวกอัตโนมัติทุกออเดอร์ (ไม่มีวันถูกหัก) ส่วนพอยท์ไม่ auto — ยอดพักไว้ที่ "รอแปลงเป็นพอยท์" ให้ลูกค้ากดแปลงเองทีหลัง แยกกันเด็ดขาด** → ปลดล็อกรางวัลขั้นบันไดตามยอดสะสม กดขอรับสิทธิ์ กรอกฟอร์ม เห็นในประวัติของตัวเอง **ทุกกติกาอ่านสดจาก `admin.html` ผ่าน `shared-state.js`/`localStorage` ไม่มีค่าฝังในหน้านี้เอง** ("ลูกค้า" ที่จำลองคือเบราว์เซอร์นี้ 1 คน เก็บสถานะแยกไว้ใน `localStorage` อีกช่องหนึ่ง ไม่ปนกับค่าตั้งของแอดมิน)
- `admin.html` + `admin.css` + `admin.js` — **ตั้งค่าฝั่งแอดมิน** ครบทุกระบบในหน้าเดียว จบไม่ต้องออกไปหน้าอื่น: ทุกช่องกรอกเป็น type ที่ถูกต้องจริง (วันที่ = date picker, เลือกสินค้า/หมวด/แบรนด์ = dropdown จาก catalog, เพิ่ม/ลบรายการ = ปุ่มทำงานจริง) preview ทุกจุดคำนวณสดจากค่าที่ตั้ง มี callout "คำถามที่ต้องถามลูกค้า" เรื่องวิธีแยกสินค้าเข้าร่วม (แบรนด์/หมวดหมู่/รายชิ้น) และทุกฟีเจอร์ที่มีกลุ่มลูกค้าเป้าหมายใช้ toggle 2 ระดับ "ทุกคน" / "บางคน" (เลือกรายชื่อเองเป็น chip list) — **ทุกค่าที่ตั้งเซฟลง `localStorage` อัตโนมัติ** (คีย์เดียวกับที่ `index.html` อ่าน) มีปุ่ม "รีเซ็ตค่าเริ่มต้น" ล้างกลับไปที่ค่าตัวอย่าง
  - โปรโมชั่น: **"โปรโมชั่นอัตโนมัติ"** — รวม 3 กลไกเดิม (ซื้อคู่สินค้าเฉพาะเจาะจง / ส่วนลดท้ายบิลแบรนด์-หมวด / ส่งฟรีที่ไม่ใช่คูปอง) ไว้ setting เดียวกัน เพิ่มได้หลายกฎพร้อมกัน แต่ละกฎเลือก **เป้าหมาย** (เจาะจงสินค้า — มิเรอร์โครงสร้างหน้าตั้งค่า Bundle/ของแถมจริงของ pmpc ทั้งหมด, หรือแบรนด์/หมวดหมู่ + ยอดขั้นต่ำ) แล้วเลือก **ผลตอบแทน** (ส่วนลดคงที่/% หรือฟรีค่าส่ง) — ไม่ว่าแบบไหนคิดเฉพาะยอด/รายการที่เข้าเงื่อนไขกฎนั้นเท่านั้น ไม่ใช่ทั้งบิล กฎแบบแบรนด์/หมวดที่แย่งกลุ่มเดียวกันใช้ priority สูงสุดที่ผ่านเกณฑ์ชนะแค่ 1 กฎ (แยกสนามกันระหว่างฝั่งส่วนลดกับฝั่งฟรีค่าส่ง) ส่วนลดตามวัน (Flash Sale) แยกเป็นอีก setting มีสวิตช์ "สถานะสำหรับจำลอง" ให้ข้ามเช็ควันเวลาจริงตอนนำเสนอ
  - คูปอง: **ทั้ง 3 แบบสร้างได้หลายรายการพร้อมกัน** ไม่ใช่ config ตัวเดียวลอยๆ อีกต่อไป — กระดาษ (สร้างได้หลายชุด แต่ละชุดคนละโค้ด คนละส่วนลด, มียอดขั้นต่ำ + เตือนเรื่องต้องผูกรายชื่อร้านที่ลงทะเบียน — ไม่ผูกกับระบบเช็คสิทธิ์ออนไลน์), ออนไลน์แบบไม่ unique (เพิ่ม/ลบโค้ดได้อิสระ แต่ละโค้ดตั้งเงื่อนไขแยกกัน เช็คทั้งโควตารวม+ต่อคนจริงทั้งตอน "ทดลองใช้โค้ด" ในหน้านี้ และตอนลูกค้าจริงใช้ที่ `index.html`), **คูปองเก็บล่วงหน้า/แจกอัตโนมัติทุกเดือน รวมเป็น setting เดียวต่อใบ** — เพิ่มได้หลายใบ แต่ละใบเลือก `distributionMode` เอง manual (ปล่อยให้กดเก็บเอง) หรือ auto_monthly (ระบบออกให้ทุกวันที่กำหนด) ผสมกันได้ในแคมเปญเดียว
  - พอยท์: อัตราแลก 2 ช่องคูณสด + กติกาปัดเศษ + แคตตาล็อกแลกของเพิ่ม/ลบ/เปิดปิดได้จริง
  - แคมเปญ: **รายการขั้นรางวัลเพิ่ม/ลบได้จริง** มองเป็นขั้นบันไดล้วน ไม่มีเงื่อนไขปลดล็อกให้เลือกและไม่มีสวิตช์ใช้ร่วมกับโปรอื่น (ตัดออกเพราะไม่เกี่ยว) — ตั้งโควตาต่อขั้นเองได้ (เว้นว่าง = ไม่จำกัด) พร้อมแบบฟอร์มขอข้อมูลกำหนดเอง ไม่มีวงล้อสุ่มในระบบ (ของหายากคัดเลือกนอกระบบ)
- `shared-state.js` — **แหล่งข้อมูลกลาง** ใช้ร่วมกันระหว่าง `admin.html` (เขียน) กับ `index.html` (อ่าน): แคตตาล็อกสินค้า (ชื่อ/ราคา/แบรนด์/หมวด) + ค่าเริ่มต้นของทุก setting + ฟังก์ชัน `pmpcLoadSettings`/`pmpcSaveSettings`/`pmpcResetSettings` ที่คุยกับ `localStorage`
- `style.css` — ดีไซน์/ธีมร่วมของทุกหน้า (รองรับ light/dark ตามเครื่อง)
- `explain.html` — เอกสารกระบวนการ/มติภายใน (ไม่ผูกกับเมนูหลักแล้ว เปิดตรงได้ถ้าต้องใช้อ้างอิงเอง)

ตรรกะทั้งหมดเป็น vanilla JS ล้วน ไม่พึ่ง library ภายนอก ไม่มี backend จริง — "ฐานข้อมูลกลาง" คือ `localStorage` ของเบราว์เซอร์เครื่องนั้น

## เล่นยังไง — ระบบจำลอง (index.html)

1. ตั้งชื่อ "เข้าสู่ระบบเป็นลูกค้า" ด้านบน (ใช้เช็คกลุ่มเป้าหมายที่แอดมินตั้งไว้ ถ้ามี)
2. หยิบสินค้าใส่ตะกร้า — ถ้ามีการ์ดแนะนำ "ซื้อคู่กัน" หรือแบนเนอร์ Flash Sale ขึ้นมา กดหยิบตามได้เลย ราคาคำนวณสดทุกจุด
3. ดูยอดสรุปฝั่งขวา (ส่วนลดท้ายบิล/ค่าส่ง/คูปอง) พิมพ์โค้ดคูปอง หรือกดเก็บคูปองที่เสนอไว้แล้วกดใช้จากกระเป๋า
4. กด "ชำระเงิน" — ยอดสะสมแคมเปญ (แถบรางวัลขั้นบันไดด้านล่าง) ขยับทันทีทุกออเดอร์ ทำซ้ำได้เรื่อยๆ เพื่อไล่ปลดล็อกแต่ละขั้น
5. พอยท์ไม่เข้าอัตโนมัติ — ไปที่ส่วน "สะสมพอยท์" กด "แปลงเป็นพอยท์" เองเมื่ออยากได้ (แปลงยอดที่พักไว้ทั้งหมดในครั้งเดียว ไม่กระทบยอดสะสมแคมเปญ)
6. ถึงขั้นไหนแล้ว กด "ขอรับสิทธิ์" กรอกฟอร์ม ดูรายการไปโผล่ใน "ประวัติคำขอรับรางวัล" ด้านล่างสุด
7. ปุ่ม "เริ่มลูกค้าใหม่" ล้างตะกร้า/แต้ม/ยอดสะสม/ประวัติของลูกค้าจำลองคนนี้ (ไม่กระทบค่าที่ตั้งฝั่งแอดมิน)

## เล่นยังไง — ตั้งค่าแอดมิน (admin.html)

แก้ค่าช่องไหนก็ได้ (ชื่อ ยอดเกณฑ์ ส่วนลด โควตา กลุ่มลูกค้าเป้าหมาย ฯลฯ) แล้ว preview ในหน้าเดียวกันจะคำนวณสดให้ดูทันที — ถ้าเปิด `index.html` ไว้อีกแท็บ สลับไปดูจะเห็นการเปลี่ยนแปลงจริงที่ฝั่งลูกค้าเช่นกัน (แอดมินเซฟค่าลง `localStorage` ทุกวินาที)

ข้อมูลทั้งหมดอยู่ใน `localStorage` ของเบราว์เซอร์เครื่องนั้นเท่านั้น ล้าง site data หรือเปิดเบราว์เซอร์อื่นแล้วหาย — เป็น prototype สำหรับคุยไอเดีย ไม่ใช่ระบบจริง ไม่มีการชำระเงินจริงเกิดขึ้น
